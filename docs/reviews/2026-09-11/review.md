# Disease Atlas UI/UX·투어 업그레이드 검토

검토일: 2026-09-11 · 기준: `master`, `3dab4c5`

## 결론

어두운 해부 도판과 별자리 그래프라는 시각적 정체성을 유지하면서, **처음 방문한 사람이 쉽게 시작하고, 질병 사이의 연결을 이해하며, 학습을 이어가는 경험**을 강화하는 것이 가장 효과적이다.

우선순위는 **투어 상태 오류 수정 → 모바일 탐색 개선 → 투어 2.0 → 비교·공유·복습**이다. 새 질병이나 투어 개수를 늘리기 전에 기존 3개 투어의 경험을 완성하는 편을 권한다.

## 2. UI/UX 방향: 시작점이 보이는 지도

### 첫 화면

지금은 전체 지도가 먼저 나오고, 검색과 투어가 작은 버튼으로 배치된다. 축소된 질병명은 특히 모바일에서 읽기 어렵다. 첫 방문자에게 다음 행동을 안내하는 작은 시작 카드를 추천한다.

- ‘3분 동안 질병의 연결을 알아보세요’ 같은 학습 초대 문구.
- 대표 투어 1개와 ‘전체 투어 보기’, ‘자유롭게 둘러보기’.
- 부위 선택 시 그 부위를 읽을 수 있는 배율로 확대.
- 첫 방문 안내는 닫을 수 있고 나중에 다시 열 수 있게 구성.

전체 지도에서는 부위와 주요 연결을 보여주고, 확대하면 질병명이 충분한 크기로 나타나는 **확대 수준별 정보 표시**를 제안한다. 현재의 명조 제목, 따뜻한 글자색, 부위색은 유지하되 작은 영문 메타데이터보다 한국어 행동 버튼의 위계를 높인다.

### 탐색과 관계 설명

- 지도 상단에 ‘전체 → 내분비 → 고지혈증’처럼 현재 위치를 표시.
- ‘전체 지도 / 선택 질병 주변 / 투어 경로’ 보기 모드 제공.
- 관계선 선택 시 관계 종류·방향·한 줄 설명을 보여줌. 현재 상세 패널에서 보이는 관계 정보를 지도에서도 이해할 수 있게 확장.
- 모든 관계선을 동시에 켜는 것보다 현재 목적에 맞는 연결을 선별해서 표시.
- 모바일에서는 기본적으로 ‘지도 / 목록’을 전환할 수 있게 해 작은 노드를 정확히 누르지 않아도 탐색 가능하게 함.

## 3. 가장 추천하는 기능: 투어 2.0

### A. 고르기

작은 드롭다운을 투어 라이브러리로 확장한다. 각 카드에는 학습 질문, 예상 시간, 단계 수, 난이도, 방문 부위, 진행 상태를 보여준다. 예상 시간은 실제 읽기·조작 시간을 측정해서 조정한다.

예시 카드 구성: **떨림의 정체 · 입문 · 4단계 · 비슷한 증상을 어떻게 비교할까?**

주제는 ‘혈관’, ‘신경’, ‘대사’ 등으로 묶고, ‘처음이라면’, ‘이어서 보기’를 별도로 제공한다. 기존 투어 수가 적은 단계에서는 복잡한 검색·필터보다 3개 카드를 직접 노출하는 것으로 충분하다.

### B. 따라가기

현재 투어는 한 질병을 선택하고 그 질병의 모든 이웃 관계를 강조한다. 이를 **이전 단계 → 현재 단계 → 다음 단계**의 경로를 설명하는 방식으로 바꾼다.

- 현재 단계 번호에 더해 전체 경로 미리보기와 클릭 가능한 단계 목차.
- ‘왜 다음 질병으로 이동하나요?’를 설명하는 짧은 연결 문장.
- 현재 단계와 설명에 필요한 관계선만 우선 강조.
- 카드가 차지하는 공간을 제외하고 관련 노드를 화면 안에 배치.
- 데스크톱은 옆 해설 패널, 모바일은 접을 수 있는 하단 카드.
- ‘자세히 보기’로 질병 상세를 열어도 투어 위치 유지.
- 이전·다음·나가기 유지, 모션 감소 설정에서는 카메라 애니메이션 생략.

**학습 순서와 질병의 진행 관계를 구분해야 한다.** 특히 비교·감별을 설명하는 투어의 다음 단계로 이동한다고 해서 질병 A가 B로 진행한다는 뜻은 아니다. 투어 경로는 별도 학습 경로로 표시하고, 실제 관계 종류는 기존 데이터에 따라 명시한다. 의료 관계선을 단계 순서만으로 자동 생성하지 않는다.

구현 방향: `TourStep`에 학습 목표·핵심 문장·전환 설명을 추가하고, 필요한 관계만 참조할 수 있게 한다. 카메라는 고정 `zoom: 1.2` 대신 선택 노드 집합과 남은 화면 크기를 기준으로 계산한다. React Flow는 특정 노드와 padding을 지정하는 `fitView` 옵션을 제공한다. [공식 문서](https://reactflow.dev/api-reference/types/fit-view-options)

### C. 마무리와 다시 방문

지금은 마지막 ‘투어 마치기’가 일반 종료와 같은 함수를 호출해 카드만 사라진다. 학습 완료를 별도 상태로 만든다.

- 핵심 내용 3줄과 방문한 질병 목록.
- 이해 확인 질문 1개와 설명이 있는 피드백.
- 관련 투어 추천, ‘이 경로를 지도에서 다시 보기’.
- 중간 단계·완료 상태를 브라우저에 저장하고 ‘이어서 보기 / 처음부터’ 제공.
- 로그인은 초기 버전에 필요하지 않음. 저장 실패·이전 콘텐츠 버전에서도 앱이 정상 동작하도록 처리.

신규 투어는 이 흐름을 기존 1개 투어에 먼저 적용한 뒤 늘린다. 새 주제 후보는 증상 중심 비교, 한 부위 집중 탐색, 여러 부위를 연결하는 주제 탐색이다. 구체적인 질병 관계와 해설은 출처 확인 후 확정한다.

저장소의 기존 v1.2 문서에도 URL·공유, 증상 역탐색 계획이 있다. 해당 기능은 새 아이디어로 중복 기획하기보다 기존 계획과 통합하는 것이 좋다.

## 5. 접근성과 검증 보강

검색은 키보드 화살표·Enter를 지원하지만 입력의 명시적 이름, combobox/listbox 관계, 활성 결과 전달이 빠져 있다. 검색 오버레이에는 적절한 대화상자 의미, 포커스 이동·복귀를 추가한다. 부위·관계 토글에는 `aria-pressed`, 투어 단계에는 제목과 진행 변경 알림을 제공한다. [W3C Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/), [W3C Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

현재 `prefers-reduced-motion`은 CSS animation만 끄므로 `setCenter`의 600ms 이동과 CSS transition도 함께 검토한다. 44px 터치 영역은 이번 개선의 사용성 목표이며 현재 28px 버튼을 수치만으로 WCAG 위반으로 판정한 것은 아니다.

다음 구현에서는 이번에 재현한 상태 충돌을 중심으로 브라우저 회귀 검증을 추가하는 것이 유용하다.

- 투어 중 포인터를 다른 질병에 올려도 현재 단계 강조가 유지된다.
- 현재 단계가 필터로 숨겨지지 않으며 종료 후 이전 탐색 상태가 복원된다.
- 모바일에서 카드와 학습 대상이 동시에 보인다.
- 뒤로·다음·직접 단계 선택·새로고침·이어보기가 같은 학습 위치를 가리킨다.
- 검색을 키보드만으로 열고 결과를 선택하며, 닫으면 적절한 곳으로 포커스가 돌아간다.

## 6. 권장 구현 순서

1. **안정화**: 투어 hover·필터 충돌, 기존 린트 실패, 영문명 검색, 화면 크기 변경 시 지도 복구.
2. **투어 2.0 첫 버전**: 추천 진입 카드, 단계 목차, 경로 강조, 모바일 시트, 완료 요약, 브라우저 이어보기. 기존 1개 투어로 끝까지 검증.
3. **탐색 확장**: URL 공유·뒤로가기, 질병 비교, 즐겨찾기, 증상 일치 설명.
4. **콘텐츠 운영**: 출처·검토일과 편집 흐름을 갖춘 후 투어 주제 확장.

가장 먼저 만들 묶음은 **‘투어 상태 안정화 + 경로 강조 + 모바일 시트 + 완료 요약’**이다. 사용자가 요청한 UI/UX와 투어 기능을 한 번에 체감할 수 있으며, 현재 그래프와 콘텐츠를 재사용할 수 있다.
